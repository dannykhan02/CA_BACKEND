Run the following in the worker's application directory (normally `/app`). It reads Horizon's own configured Redis connection, not the application's PostgreSQL failed_jobs table. It does not retry, forget, clear or modify jobs. The two sorted sets use negative Unix timestamps in this installed Horizon version. The interval below is inclusive of 13:43:00 through 13:47:00 UTC.

```sh
php <<'PHP'
<?php
require getcwd().'/vendor/autoload.php';
$app = require getcwd().'/bootstrap/app.php';
$app->make(Illuminate\Contracts\Console\Kernel::class)->bootstrap();
$start = strtotime('2026-09-13 13:43:00 UTC');
$end = strtotime('2026-09-13 13:47:00 UTC');
$redis = Illuminate\Support\Facades\Redis::connection('horizon');
$ids = [];
$sets = [];
foreach (['failed_jobs', 'recent_failed_jobs'] as $set) {
    $count = (int) $redis->zcount($set, -$end, -$start);
    $sets[$set] = ['matching_references' => $count];
    if ($count > 500) {
        throw new RuntimeException('Over 500 references: narrow the time interval before exporting.');
    }
    foreach ($redis->zrangebyscore($set, -$end, -$start) as $id) {
        $ids[$id] = true;
    }
}
$records = [];
foreach (array_keys($ids) as $id) {
    $fields = ['id', 'name', 'queue', 'connection', 'status', 'failed_at', 'exception'];
    $values = $redis->hmget($id, $fields);
    $row = array_combine($fields, array_values($values));
    $row['reference_id'] = $id;
    $row['ttl_seconds'] = (int) $redis->ttl($id);
    $row['record_missing'] = $row['id'] === null || $row['id'] === false;
    $exception = (string) ($row['exception'] ?? '');
    $row['exception_class'] = preg_match('/\A([^:\r\n]+): /', $exception, $m) ? $m[1] : null;
    // Keep the complete original string, including nested exceptions and stacks.
    $row['failed_at_utc'] = is_numeric($row['failed_at'])
        ? gmdate('Y-m-d\TH:i:s\Z', (int) $row['failed_at']) : null;
    $records[] = $row;
}
usort($records, fn ($a, $b) => (float) $a['failed_at'] <=> (float) $b['failed_at']);
echo json_encode([
    'captured_at_utc' => gmdate('c'),
    'railway_environment' => getenv('RAILWAY_ENVIRONMENT_NAME') ?: null,
    'railway_service' => getenv('RAILWAY_SERVICE_NAME') ?: null,
    'railway_deployment_id' => getenv('RAILWAY_DEPLOYMENT_ID') ?: null,
    'horizon_prefix' => config('horizon.prefix'),
    'window_utc' => ['2026-09-13T13:43:00Z', '2026-09-13T13:47:00Z'],
    'sets' => $sets,
    'records' => $records,
], JSON_PRETTY_PRINT | JSON_UNESCAPED_SLASHES | JSON_INVALID_UTF8_SUBSTITUTE | JSON_THROW_ON_ERROR), PHP_EOL;
PHP
```

Preserve the output as incident evidence. The `exception` field contains the exact retained message/class/stack, not a new exception generated by this reader. Job payloads and Redis credentials are not exported. Treat any document data already embedded in the stored SQL exception as private incident evidence.

An empty result means no matching references in the **currently configured namespace**, not proof that nothing failed. If empty, check whether the incident deployment used another Horizon prefix/Redis instance, or whether Horizon forget/clear was used. Expired hashes can leave references without exception bodies; the export distinguishes these via `record_missing` and TTL. A retained final-attempt exception may still be only the cascade, not the original trigger.
