# Large document synthesis coverage

## Cause and behavior

The old `EvidenceBudget::forDocument()` sorted persisted evidence, serialized every full record (including repeated source quotes), and stopped at 16,000 **bytes**. The CBK report had 799 persisted records but only 11 fit. The summary request could not consider the other 788. The old `evidence_omitted` counter conflated this omission with incomplete extraction, while normal executive selection was not separately measured.

`SynthesisCoverage` now projects only typed claims, material qualifiers, the original source ID and evidence record ID, and minimal page/span/offset citations. It never edits stored evidence or slices a JSON record. The 16,000-byte bound is a conservative upper bound for text tokens in each batch; the provider's own request admission also checks the model context and exact configured price. Groups use 40-page (or 100,000-character) sections and evidence kind, with a round-robin schedule and a 48-batch ceiling. Oversized records and excess groups are enumerated as uncovered.

Documents whose compact evidence fits one request still use one synthesis call. Larger documents send each group to a small structured selection call. Every returned ID and claim must match the supplied original compact record exactly. The final call receives selected **original** records, with one representative per completed group and explicit beginning/middle/end anchors. Its published factual sentences are copied from those validated records with source IDs; unsupported model prose is discarded. The V2 analysis composer still derives charts, analysis groups, findings and takeaways independently from the persisted evidence.

Coverage now separates extraction failure (`failed_chunks`, `saturated_chunks`), validation rejection (`dropped_records` / `validation_rejected`), synthesis consideration (`synthesis_considered`, `synthesis_uncovered`, `uncovered_groups`) and selective presentation (`presentation_selected`, `presentation_omitted`). Presentation omission does not make extraction partial. `uncovered_groups` carries each exact section/type group, reason and count. The workspace shows these group counts and reasons behind its coverage disclosure; its existing V2 analysis views remain the source for detailed intelligence.

## Budget and ownership

Each intermediate request has a durable `synthesis_batch` chunk keyed by its exact input hash and scoped to the pipeline. Its document-lock claim reserves the configured maximum request cost plus a protected final evidence-only synthesis and repair. The provider/AI-credit attempt admission remains in force for each call. Settlement occurs before the next batch job is dispatched. A duplicate job observing a running chunk waits; recovery marks interrupted calls uncertain and those groups become uncovered instead of being sent again. Transient failures can retry within the configured attempt limit. Budget denials, timeouts and invalid outputs remain visible as uncovered groups. The final summary and Revision V1 publication still use the existing ownership check and synthesis checkpoint. No cap is raised.

Truncated extraction continuations now reserve against a protected evidence-only final request, its repair, and one batch. The continuation's preflight includes its counted prior input plus continuation envelope, while its actual admission still prices the exact counted request under the document lock. Running siblings defer denial until their reservations settle. This avoids a rejection caused only by holding both a full-source synthesis and a fallback after a paid truncation. It can still deny a continuation if the actual bounded request plus protected final work exceeds the document cap.

## Local regression measurements

The deterministic 799-record fixture mirrors the production type counts (546 metrics, 110 definitions, 110 facts, 23 entities, 6 deadlines, 3 obligations, 1 risk). It has dense table-style metrics, two conflicting capital-ratio figures, and findings across 120 pages. The legacy path includes **11/799** and omits **788**. The compact plan has **23** bounded batches and accounts for **799/799**; the executive merge intentionally receives fewer records. The test verifies that the configured maximum intermediate cost plus the final synthesis and repair reservation and the reported $0.863037 prior spend remain below $2.00. These are conservative request ceilings for the fixture, not a forecast of actual token usage for the real report.

Processing adds up to one provider call per batch plus a final call. The fixture adds 23 serial, at-most-60-second calls, so queue wait and provider latency will dominate elapsed time. The 48-batch cap prevents unbounded calls. If actual evidence is longer, the budget or batch cap may leave groups uncovered; the final result says which ones. Intermediate responses can select at most eight claims per group, and the final summary remains selective. Verbatim quote semantics outside the typed claim fields are not reinterpreted by this compact projection; operators should inspect the original evidence for nuanced context.

## API and legacy arrays

The legacy `entities`, `risks`, and `deadlines` arrays are backed by derived rows, not by every extracted evidence record. The merge creates derived rows, but Revision V1 readers pin those arrays to the **published** revision. A partial candidate that has not completed summary/publication can therefore have persisted evidence while the API correctly returns empty legacy arrays. The new budgeted synthesis path permits a grounded, explicitly partial summary to publish when final funds remain. The V2 analysis reads the published evidence set and is the appropriate view for non-actionable definitions, facts and metrics. Do not populate legacy actionable arrays directly from all evidence.

## Safe rollout and rollback

1. Deploy schema-free backend and frontend code together with the default `hierarchical_synthesis=true`. Run the affected local test suites and check the 799-record fixture, provider-attempt ledger, per-document spend, `synthesis_batch` statuses, and coverage fields in a canary document processed **after** deployment. Do not reprocess existing documents merely to populate the new fields.
2. Keep the existing per-document and workspace credit caps. Monitor batch count, budget-denied groups, uncertain calls, timeout frequency and total synthesis latency. A production report may be partial if its actual compact evidence exceeds the fixture's size.
3. To stop new hierarchical synthesis work, set `DOCINTEL_HIERARCHICAL_SYNTHESIS=false` through the normal configuration deployment process or redeploy the prior code. Drain in-flight jobs first; a running old/new worker mix can interpret a pending batch plan differently. No database rollback is required. Persisted evidence and completed batch checkpoints remain; the prior path again selects a byte-limited subset and must be treated as a temporary rollback, not as complete coverage.

No production data, Railway variables, deployments or document reprocessing were changed by this local implementation.
