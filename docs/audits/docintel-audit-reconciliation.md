## Outstanding issues ranked by correctness impact

1. **Critical — accepted analytical facts without proved governing entity.** The latest live run has 14 eligible observations and zero verified subject roles. This is a measured trust-boundary gap for company-scoped output, even though its matched numbers and arithmetic were correct. Define and test owner versus population proof before any activation decision.
2. **High — structural PDF and multi-entity attribution ceiling.** Caption-dated/transposed tables, irregular geometry, and real group ownership remain unproved. Current tests show narrow fail-closed cases, not a general owner relation or cell model.
3. **High — no real-document correctness denominator.** No registered authorized case was found; Northstar is fictional. False acceptance and false rejection rates for DOCX, XLSX, scans, contracts and real group reports are unknown. Complete independently reviewed positive and negative cases before rollout.
4. **Medium-high — quantity and period proof gaps.** Unitless counts, cross-page definitions and bare-quarter operational periods lose supported information. Preserve refusal until exact, bounded links and population kinds are proved.
5. **Medium — source/report trust semantics.** V9 model charts remain available through a frontend that still calls non-document origins legacy; source quote/API mappings do not establish semantic correctness. Complete frontend contract handling and stable result selection.
6. **Medium — prompt and verifier complexity.** V10 still asks for four role citations and per-period enumeration; the PDF verifier retains a document-shaped stoplist and proposal special case. The flagged server path reduces some work but only supports aligned PDF rows. Simplify only after corpus-backed comparison of coverage, false acceptance, latency and cost; no new paid run is authorized by this report.
7. **Medium — revision and security rollout visibility.** The code has publication/authorization controls, but effective production flags, worker versions and historical provenance were not checked. Keep the Revision V1 and V2 activation gates separate from code-level status.

## Evidence interpretation and next decision

The latest Northstar report supports **20/21** unique row/value/period matches in mode B, **16/21** proved cited cells, **14/21** analytically eligible observations, four financial series, eight deterministic comparisons, and **zero** fully proved owner-inclusive facts. It reports no wrong printed numerical value among the matched facts, but it has no negative real-document corpus from which to estimate a general false-acceptance rate. The earlier 20-observation V10 run and its frozen replay answer a different question and should retain their separate counts.

The next reviewable engineering sequence is: specify owner/population proof and regression cases; assemble authorized multi-format source gold; then assess PDF cell geometry, count definitions, period relationships and prompt simplification against those cases. Keep `DOCINTEL_SERVER_EVIDENCE_RESOLUTION` default off until the owner and real-document gates are met. This document records recommended work only; it implements none of it.
