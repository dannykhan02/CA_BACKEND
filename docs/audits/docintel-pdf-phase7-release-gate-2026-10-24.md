# DocIntel Phase 7 — verified PDF chart release gate

Date: 2026-10-24. Backend branch: `feat/docintel-pdf-table-structure`, starting at `eab4a60`. Frontend branch: `feat/docintel-verified-pdf-chart-client`. Decision: **keep the restricted native-text feature default-off; do not deploy yet**. This audit extends the [Phase 6 decision](../architecture/docintel-pdf-phase6-decision-2026-10-24.md) without changing its parser scope.

## Contract defect and repair

`VerifiedPdfChartPersister` stored `source_metadata.origin=verified_pdf_table`, but `ChartResource` recognized only `document_visual` and `model_unverified`. The public document API therefore labeled a proved PDF comparison as a historical chart with `renderEligible=false`, while the intelligence API independently returned the same logical comparison. The frontend could show two cards for one comparison. The source reference endpoint also rejected a valid Apple value as ambiguous because the candidate carried both a row citation and a precise cell proof.

The document API now reports `sourceOrigin=verified_pdf_table` and an additive `logicalChartId` only for this origin. `renderEligible`, exact value status, unit and point data are exposed only after a read-time check of the live document/file hash, published intelligence revision and provenance set, current structured extraction, recomputed eligible candidate, independently verified evidence, value-role graph binding, exact anchor text/offset/page, and stored points. If any check fails, the chart keeps its identity but returns `renderEligible=false`, empty `data` and `sourceIds`, and a source-proof-unavailable reason. Legacy chart responses keep their prior shape and eligibility policy. The generated intelligence chart also receives the same logical ID. Clients display the persisted chart when it is eligible, otherwise the current generated chart; both evidence stores remain separate. No stored origin was rewritten.

The source resolver allows the precise cell reference only when one redundant untyped row citation contains the exact value span on the same page; other ambiguous references still fail. Changed file/text revisions return `STALE_SOURCE_REFERENCE`. The metric integrity gate also compares a recorded PDF file hash to the live document hash. A presentation-only reconciliation hides an equivalent *independently verified* model observation when metric label, exact magnitude, period, unit/currency, accounting/value basis, scope/owner, source revision, provenance set and value anchor agree. The source finding exposes `equivalentSourceIds`; underlying model and source evidence IDs and graph rows remain intact. Conflicts and unverified model claims remain visible. Source candidates are excluded from direct synthesis evidence inputs, so the new path adds no source-candidate model request or billing event.

## User workflow evidence

The committed Apple fixture is the original three-page PDF from the audit, SHA-256 `e333dd821d9ef827e82d8e0b696493a127c4ee171ea63aca3a80dc1dfea60e89` (3,147,962 bytes). `VerifiedPdfAppleWorkflowTest` uploads it through `POST /api/documents`, then executes the application's scan, extraction, planning, chunk extraction, merge/publication and synthesis **job handlers** in queue order for stage measurements. A separate test dispatches the same upload onto Laravel's serialized **database queue** and runs a local Laravel worker through chart publication; it reaches `Ready` and four eligible charts without calling handlers directly. External provider HTTP is mocked and stray requests are prohibited in both runs. The mock includes one exactly equivalent model fact (`Operating income 72,421`) and one conflicting claim (`72,422`). The handler test fetches the real `GET /api/documents/{id}`, intelligence and source-reference endpoints. It asserts 18 verified source observations, four eligible persisted Apple charts/eight points, four corresponding generated logical IDs, 134 raw versus 133 presented findings, one reconciled equivalent, visible conflicting limited claim, and no verified balance-sheet chart. Every exposed point has a PDF evidence ID, value anchor, exact printed value, offset and page. A source jump returns `CURRENT` with the matching value and range. A second user in another workspace receives 403 for both public responses.

The controlled merge interruption occurs immediately after `PdfSourceCandidateCollector::collect()` and before provenance publication. At that point 132 candidate rows exist, but zero are verified, zero charts or provenance sets exist, and the public analysis has no eligible chart. Retrying the same merge job through the local **database queue worker** publishes four charts/eight points; a completed-job retry leaves evidence, sets, anchors, relationships, charts and points unchanged. An unrelated document in another workspace is untouched. Changing the file hash or extracted-text revision makes document charts ineligible, removes generated charts and makes source jumps stale; old PDF source facts also fail the analytical integrity gate. Feature-off makes PDF charts ineligible with no point data. The controlled stop was an exception in the job handler, not an operating-system process kill; Redis/Horizon and concurrent retry behavior remain untested.

The Chromium check serves the **captured public HTTP responses** into the real frontend chart and source components. It found four unique cards, two leading verified PDF comparisons with the others behind “Show more,” no historical label, a visible partial-table limitation, and a point jump to Apple page 3 and exact value `57,552`, with no page errors. A unit test also suppresses the duplicate generated card in the classic document view. CSV uses each point's own PDF page and source ID; report export and dashboard use the same logical identity. The browser check does not exercise an authenticated live PDF canvas highlight; the API's exact page/value anchor is verified separately.

## Release gate

The limited capability works in the tested local Apple workflow and stays safe under the tested interruption, worker retry, changed-revision, unsupported-layout and workspace boundaries. The release gate is **not yet open**: Redis/Horizon delivery and process-kill recovery were not exercised, source navigation was validated through the public endpoint and chart UI rather than a live authenticated PDF viewer highlight, and no concurrent retry, production latency percentile or general accuracy corpus exists. Before enabling a beta, run a disposable Redis worker crash/retry and live PDF viewer point-highlight check, then review the limited-document wording with users. Keep `DOCINTEL_PDF_TABLE_STRUCTURE=false` by default. No paid inference, production write, deployment, merge or billing change occurred.
