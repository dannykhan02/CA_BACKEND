## Existing identity chain and limits

- `operation_quotes.operation_key` names one customer-credit attempt and stores the immutable provider cap. `CreditAccountant` owns exactly-once customer debit/release; provider-cost attempts are separate from customer credits.
- `provider_call_attempts.id` is a UUID for **one local Anthropic transport attempt**. The quote row lock serializes competing reservations. `reserved → dispatched → settled/uncertain` and pre-dispatch `reserved → released` are idempotent. A timeout after dispatch retains its hold. A killed worker after dispatch may leave `dispatched` indefinitely; there is no reconciliation policy yet.
- `document_ai_runs.provider_attempt_id` associates a usage row with the attempt, and `OperationSpend::spentUsd` excludes those rows from the older run sum to avoid double counting.
- Chunk dispatch tokens, input hashes, and B2 checkpoints prevent many stale/duplicate jobs, but they do not create a universal logical-request identity at the common HTTP boundary. A new job invocation that passes a stage guard can create a fresh attempt UUID.
- `ProviderRequestAdmission` estimates input plus maximum output from configured Anthropic prices and enforces a per-call ceiling. For documents it compares **that call** with the document budget. Only a quote-backed `reserveAttempt` adds active and settled attempts into an atomic cumulative cap. The actual provider usage can exceed the estimate; the code settles actual usage without a hard post-response cap.
- `OperationSpend::assertCallAllowed` accepts an explicit quote on status alone. It does not currently verify quote kind, resource ID, workspace ID, or caller task. That is a scope-integrity risk if a wrong quote ID reaches `forOperation`, even though the known production callers obtain IDs locally.

## Phase 2A.2 decision points before changing runtime behavior

1. **Preserve the green baseline.** Keep dedicated quote-backed KPI adjudication, approved models and configured Sonnet 5.5 pricing, sanitized model diagnostic, migration rollback order, and existing B1/B2 semantics.
2. **Close wrong-quote attribution first.** Comparison and metered Q&A need explicit quote-kind/resource/workspace matching before HTTP. A null comparison quote in credits mode must not fall through to a document quote. Free Q&A and legacy comparison must retain their intentional product behavior while receiving a separate spend policy. `AiCreditsTest::test_ocr_and_comparison_and_analysis_spend_are_attributed_to_their_own_operation` deliberately passes a comparison quote to an OCR call; that fixture would need to become a legitimate comparison call if strict binding is introduced. Its current expectation is evidence of the missing scope check, not a reason to keep it.
3. **Choose one budget owner for unquoted Anthropic work.** The existing quote table is the natural lock for credit-mode operations, but disabled/legacy/free paths have no quote. A per-document or per-workspace operational spend scope needs an atomic durable hold that does not debit customer credits or rewrite the legacy billing ledger. Define its cap and lifecycle before inserting records; avoid pretending a per-call limit is cumulative.
4. **Treat Voyage as a distinct provider boundary.** Price/model, request size, retry, response logging and cost scope need explicit policy. Query embedding is invoked after `QaGuard::admit` but before the Anthropic answer, and also by search GET, so placing an answer-only guard in `AnthropicClient` cannot cover it. Do not claim all reads are provider-free; the invariant covers Brief GET, while search GET is currently a paid query path.
5. **Reconcile abandoned Anthropic attempts conservatively.** Expired `reserved` rows can be released only with proof that dispatch never happened. Expired `dispatched` rows need an auditable uncertain transition retaining the hold. No network exactly-once claim is possible from the local UUID.
6. **Keep privacy in the same boundary work.** Remove the full Voyage response body from production error logs and sanitize parser/provider errors surfaced to users. Metadata can retain status, model, request ID, usage and typed failure code.
