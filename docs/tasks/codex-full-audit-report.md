### 1. Cost burn and truncation

**Verified:** All paid Anthropic messages found in `app/` go through `AnthropicClient::callWithRetry` at [AnthropicClient.php](../../app/Services/AnthropicClient.php#L573), which checks operation spend and obtains a provider permit per HTTP attempt. Model lookup and token-count endpoints also use the gate and do not generate output. Complete truncated extraction records are parsed and checked with a literal source substring at [EvidenceSchema.php](../../app/Services/AI/Incremental/EvidenceSchema.php#L93); this does **not** use whitespace normalization, so the proposed normalization false positive is not present. The continuation ancestry check caps descendants at two at [IncrementalPipeline.php](../../app/Services/AI/Incremental/IncrementalPipeline.php#L628); each request gets its own run row and the chunk settlement sums those rows. The extraction system block has `cache_control: ephemeral`, but actual cache hits cannot be established without production runs. Pricing constants match the current [Anthropic pricing table](https://platform.claude.com/docs/en/about-claude/pricing) for Haiku 4.5, Sonnet 4.6 and Sonnet 5.5; `AiPricing` correctly adds input, output, cache-write and cache-read tokens. `docintel:ai-usage-report` sums **stored estimates**, so agreement with its own constants is not invoice reconciliation. `docintel:verify-models` without `--check-access` checks routing only; access checking would make a provider request and was not run.

**Unverified:** The October 5 $6.57 spike, 74 calls/$1.41/7.39x for `sector_report.pdf`, the $0.14 Sonnet call, zero cache tokens, and the post-fix $0.355 document are historical production measurements in the supplied notes, not reproducible from this test database. The note's $0.2132 + $0.1186 + $0.0235 = $0.3553 rounds to $0.355. No invoice or production `document_ai_runs` was available. See F02, F06, F11 and F13.

### 2. Queue isolation and gate

**Verified:** [QueueTopology.php](../../app/Support/QueueTopology.php#L41) maps every listed job class; extraction and synthesis each default to two production processes, and default to two, through `config/horizon.php`. The jobs holding permits have 90–200 second timeouts; the 330-second merge does not hold a permit. Thus the 240-second lease exceeds the held job timeout, and Redis `retry_after` is clamped to 390 seconds, above the 360-second worker timeout. Lua admission, expiry and priority changes are one Redis script; acquire errors fail closed. Release errors are logged and do not replace a paid response. `HORIZON_AUTHORIZED_EMAILS` is read from cached config. The dispatch-token migration is additive and reversible on PG18; its ordinary index creation takes a write lock, so deploy it separately from a traffic peak. `document_chunks` gained `dispatch_token` in the throwaway PG18 schema.

**Limits:** A Redis crash loses permits until TTL; priority callers can occupy all free slots during sustained priority traffic. Busy jobs clone and re-enqueue without a deferral count, so sustained saturation can defer forever. Dispatch tokens reject a superseded non-null token before claiming work, and the locked claim rejects completed work. Pre-migration null-token deliveries are a compatibility exception. See F08 and F11.

### 3. AI credits

**Verified:** Default flag is false; quotes are priced 4/10/30/80 credits at 6k/30k/90k/250k tokens and dense inputs shift one band. Cap is `credits × $0.027`; OCR is `20 + max(0,pages−20)` credits for 1–60 pages, with a separate `pages × $0.02` provider cap; comparison is 12. Trial 20 and referral 100 are config defaults. `reserve`, `settle`, and `release` serialize on the workspace row and use quote-specific ledger references. Lazy saved-unit conversion is inside the same transaction and only converts `ceil(shortfall/10)` units. The 47 `AiCreditsTest` methods, four concurrency methods, and four (not three) `CreditEconomicsReportTest` methods were present and included in the passing suite. Their assertions cover state changes and concurrent balances, but the counter reconciliation test seeds its own period grant; it does not prove historical balances. No five-line mutation experiment was run because it would require writing application code, contrary to the instruction that only this report may be written.

**Boundary:** The four caps are $0.108/$0.270/$0.810/$2.160. The `classify` floor is `max($0.05,synthesis reserve) + $0.006/1k tokens`. On the incremental route, the documented synthesis reserve makes 4 and 10 credits unreachable under normal inputs; the reported 27k example's $0.3553 would exceed the 10-credit cap by $0.0853. This is a trace plus an unverified historical sample, not a measured band distribution. `operation_quotes` has unique operation keys and useful indexes, but no database check constraints for positive credits/cap, status vocabulary, or immutable price fields. Its `down()` drops the additions. PG18/pgvector exercised the migrations in the suite, so the older “PG16 only” caveat no longer applies to this local test; production lock duration is still unmeasured. See F01–F04, F09–F11 and F14.

For a **read-only production** operation reconciliation after authorization, run the following query; it returns workspace IDs with a mismatch. The durable source for all attempts is `credit_ledger`, because `billing_operations` keeps only the latest attempt for each resource. The existing synthetic tests prove their seeded scenarios, not a historical production ledger sum. Opening saved balances predate the ledger, so a naive all-time ledger sum is not equal to every saved counter.

```sql
WITH l AS (
  SELECT workspace_id,
    COALESCE(SUM(amount) FILTER (WHERE reference LIKE 'ai_reserve:%'), 0) reserved,
    COALESCE(SUM(amount) FILTER (WHERE reference LIKE 'ai_debit:%'), 0) debited,
    COALESCE(SUM(amount) FILTER (WHERE reference LIKE 'ai_release:%'), 0) released
  FROM credit_ledger GROUP BY workspace_id
), o AS (
  SELECT workspace_id, COALESCE(SUM(amount_reserved), 0) open
  FROM billing_operations
  WHERE status = 'reserved' AND amount_reserved IS NOT NULL
  GROUP BY workspace_id
)
SELECT l.workspace_id, l.reserved, l.debited, l.released,
       COALESCE(o.open, 0) AS open
FROM l LEFT JOIN o USING (workspace_id)
WHERE l.reserved <> l.debited + l.released + COALESCE(o.open, 0);
```
