# DocIntel intelligence architecture worklog

Updated: 2026-10-19. Status: **In progress**. This is the authoritative live record for the current intelligence integrity work. The older [architecture audit](../intelligence-v2/current-architecture-audit.md), [V2 contract](../intelligence-v2/intelligence-v2-contract.md), [chart contract](../CHART_SOURCE_CONTRACT.md), and [KPI identity contract](../KPI_IDENTITY.md) remain historical or component references; reconcile conflicts here against current code.

## 1. Project objective and non-negotiable invariants

Deliver source-grounded measurements and reproducible analytics across normal and incremental processing. Model output is a candidate. A rejected field, unsupported unit, ambiguous period, wrong document/workspace/revision, or missing source must never enter trusted analytics. Preserve authorization, billing, retries, atomic revision publication, and accurate source navigation. No production changes or paid model calls are authorized.

## 2. Current architecture and dependency map

Embedded visuals use `AnalyzeEmbeddedVisualsJob` and `SourceChartContract`, a different source contract. The 2026-10-07 audit describes an earlier branch state and is **not** assumed current.

## 5. Architectural decisions and alternatives considered

**D1, selected:** place fail-closed rejection in shared `MeasurementIntegrity`, used by collector, API KPI resource, analysis grouper and important-findings builder. Remove duplicate reason appenders in collector/API. **D2, amended:** retain deterministic `ChartCandidateBuilder` and `ChartResource`, but enforce eligibility inside the builder too; the earlier assumption that all callers always prefilter was unsafe. Legacy AI charts remain unverified fallbacks. **D3, selected:** reuse the typed `SourceProvenance` graph for incremental field verification. Persist a verdict after graph publication; graph failure yields limited evidence. Quote-only historical rows are not upgraded. **D4, selected:** compare explicit source status words with candidate basis; do not infer approval or expenditure. **D5, selected:** use the existing tab-delimited PDF text and cited header/value spans to verify one normal-route table cell. Replacing extraction with Camelot/Docling before a corpus/runtime benchmark would add an unproven Python service. This tab verifier rejects ambiguous layout and does not claim to solve non-tab, OCR or incremental PDF tables. **D6, selected:** use installed `brick/math` for exact comparison arithmetic; retain floats only for chart presentation, with large-number presentation still a known risk. **D7, corrected:** the first repeated-PDF-value patch only changed `sourceCapabilities`; audit showed `PdfAdapter` passed a citation directly to `PdfViewer`, bypassing the policy. The adapter now suppresses both quote and citation search for an ambiguous value while preserving the page jump and evidence strip. Its regression tests exercise the actual adapter-to-viewer props.

## 6. Target architecture and data contracts

The implemented normal-route path is: V8+ candidate with `source_context` span IDs → `KpiIdentityResolver` → stored `DocumentKpi` → deterministic `NormalKpiGrounder` → `DocumentEvidence(kind=metric)` only after all required field roles pass. Failed candidates retain `grounding_rejection` and, for new runs, their four submitted span IDs; no metric evidence is created. The grounder binds document text by SHA-256, workspace/document ownership, page and offsets, exact PDF value cell when tabular, cited column/header/subject/unit relationships, and value basis. A PDF quarter-only column can use a matching same-quarter page heading as a second period source; a proposal's wrapped funding heading can use its immediately adjacent continuation. The period stays null when the source gives no proposal schedule. `MeasurementIntegrity`, `MetricCollector`, API KPI resources and `ChartCandidateBuilder` consume this proof fail closed. Generated chart numbers come from eligible observations. Incremental extraction uses its separately published source graph and field-role verifier before converging on the same read-time integrity policy. The raw model response is not a proof record.

The desired future contract also retains raw/canonical value and unit, currency/scale, concept, subject, period and basis, revision, source roles/location, verification and rejection codes across every consumer. Existing PDF normal-route proof remains deliberately narrow; an arbitrary layout is not silently promoted. V9 only changes candidate instructions and is inactive until separately evaluated and authorized.
