## 1. Project objective and non-negotiable invariants

Deliver source-grounded measurements and reproducible analytics across normal and incremental processing. Model output is a candidate. A rejected field, unsupported unit, ambiguous period, wrong document/workspace/revision, or missing source must never enter trusted analytics. Preserve authorization, billing, retries, atomic revision publication, and accurate source navigation. No production changes or paid model calls are authorized.

## 5. Architectural decisions and alternatives considered

**D1, selected:** place fail-closed rejection in shared `MeasurementIntegrity`, used by collector, API KPI resource, analysis grouper and important-findings builder. Remove duplicate reason appenders in collector/API. **D2, amended:** retain deterministic `ChartCandidateBuilder` and `ChartResource`, but enforce eligibility inside the builder too; the earlier assumption that all callers always prefilter was unsafe. Legacy AI charts remain unverified fallbacks. **D3, selected:** reuse the typed `SourceProvenance` graph for incremental field verification. Persist a verdict after graph publication; graph failure yields limited evidence. Quote-only historical rows are not upgraded. **D4, selected:** compare explicit source status words with candidate basis; do not infer approval or expenditure. **D5, selected:** use the existing tab-delimited PDF text and cited header/value spans to verify one normal-route table cell. Replacing extraction with Camelot/Docling before a corpus/runtime benchmark would add an unproven Python service. This tab verifier rejects ambiguous layout and does not claim to solve non-tab, OCR or incremental PDF tables. **D6, selected:** use installed `brick/math` for exact comparison arithmetic; retain floats only for chart presentation, with large-number presentation still a known risk. **D7, corrected:** the first repeated-PDF-value patch only changed `sourceCapabilities`; audit showed `PdfAdapter` passed a citation directly to `PdfViewer`, bypassing the policy. The adapter now suppresses both quote and citation search for an ambiguous value while preserving the page jump and evidence strip. Its regression tests exercise the actual adapter-to-viewer props.

**D8, selected 2026-10-19:** a quarter-only PDF column can be combined with the same quarter and year in the first page heading when the cited table verifier already proved the exact column/cell. Both spans are persisted as period evidence. A conflicting year still fails. This reuses the existing `EvidenceSpanSet` and `PeriodParser`; adding a new parser or accepting document-level year metadata would be weaker. **D9, selected:** the adjacent two-span proposal heading is reconstructed only when it completes the exact number of table columns and the immediately preceding caption supports the claimed budget concept. The source row must say `Total proposed`, the column must say `Proposed`, and exact value/unit/status still need proof. A null investment period remains null. **D10, selected:** unsupported explanatory scope clauses in V8 candidates stay rejected. V9 is an inactive prompt successor that requests only a source-supported population/entity; automatically stripping clauses from stored identity would silently change its meaning. **D11, selected:** use the existing bounded `structuredCall` retry and provider attempt ledger. Two measured normal-route outputs exceeded the shared 4,096 initial cap; configure initial insights/entities caps separately, retain the 8,192 correction ceiling, and leave all other operations unchanged. A global output increase or unbounded retry would raise reservation cost and latency without evidence.

**D12, selected after the GitHub PR-merge failure:** `structuredCall` knows the operation and owns retry/admission, so it is the single owner of the initial structured-output cap. An explicit request option still wins; otherwise it reads the operation cap and falls back to the generic cap. This relocates existing policy without introducing another subsystem. The environment variable names stay stable; the internal config key moves from `services.anthropic.structured_output_tokens` to `document_intelligence.structured_output_tokens` because a main-side removal of the former produced the CI fallback and a same-file relocation still conflicted in a file-level merge check. This choice replaces the caller-owned cap selection in D11; its measured values and bounded retry policy remain valid. The later integration branch contains the main merge; the cap contract still requires a fresh merged-branch test, and no assertion should be weakened to hide a mismatch.

**D13, inherited from the source-window work:** reuse immutable structured extraction and the published revision's source anchors for navigation. Format-specific, fixed-radius DOCX and XLSX windows share the existing document policy and citation resolver. Reopening uploaded files or permitting arbitrary client-chosen coordinates would break revision pinning or expand disclosure. A window shows source context only; it cannot substitute for field-role grounding. The [DOCX](../contracts/docx-structure-window.md) and [XLSX](../contracts/xlsx-cell-window.md) contracts own response details and limits; this worklog records their intelligence-pipeline relationship and remaining validation gates.

## 6. Target architecture and data contracts

The implemented normal-route path is: V8+ candidate with `source_context` span IDs → `KpiIdentityResolver` → stored `DocumentKpi` → deterministic `NormalKpiGrounder` → `DocumentEvidence(kind=metric)` only after all required field roles pass. Failed candidates retain `grounding_rejection` and, for new runs, their four submitted span IDs; no metric evidence is created. The grounder binds document text by SHA-256, workspace/document ownership, page and offsets, exact PDF value cell when tabular, cited column/header/subject/unit relationships, and value basis. A PDF quarter-only column can use a matching same-quarter page heading as a second period source; a proposal's wrapped funding heading can use its immediately adjacent continuation. The period stays null when the source gives no proposal schedule. `MeasurementIntegrity`, `MetricCollector`, API KPI resources and `ChartCandidateBuilder` consume this proof fail closed. Generated chart numbers come from eligible observations. Incremental extraction uses its separately published source graph and field-role verifier before converging on the same read-time integrity policy. The raw model response is not a proof record.

The desired future contract also retains raw/canonical value and unit, currency/scale, concept, subject, period and basis, revision, source roles/location, verification and rejection codes across every consumer. Existing PDF normal-route proof remains deliberately narrow; an arbitrary layout is not silently promoted. V9 only changes candidate instructions and is inactive until separately evaluated and authorized.

## 10. Model configuration and migration decisions

Official Claude API Haiku 5.5 ID is `claude-haiku-5-5` with no date suffix. Existing request builder omits `temperature`, `top_p`, `top_k`, manual thinking and assistant prefill; it selects returned text blocks by type. Repository defaults remain Haiku 4.5 extraction / Sonnet 5.5 synthesis; the two independently queried production documents actually used Haiku 5.5 for extraction, so the deployed environment overrides the source default. Tiered price uses all input tokens including cache reads/writes and applies the higher tier to the whole request above 100k. Official rates: <=100k $0.10 input/$0.50 output/$0.125 5m cache write/$0.01 cache read per MTok; >100k $0.50/$2.50/$0.625/$0.05. Local compatibility tests are not a substitute for live API quality/cost results. No production model switch was made in this session.

Measured truncation budget proposal: the two normal-route insights success responses used 4,815 and 5,198 output tokens; entity successes used 3,963 and 4,677. The new initial caps are 6,400 for insights and 6,144 for entities, with the unchanged 8,192 correction ceiling. Other structured operations retain the generic configured cap (4,096 default). Relative to the old 4,096 reserve, the extra *maximum* provider reservation at Haiku 5.5's short-context output rate is about $0.001152 per insights request and $0.001024 per entities request; actual cost depends on generated tokens. On the first queried document, failed first attempts cost $0.002748 + $0.002540 estimated and consumed 16 + 15 seconds before successful 17 + 14 second corrections. Avoiding truncation could save those failed attempts, but that is a hypothesis until observed after rollout. A larger cap does not guarantee shorter output or eliminate malformed JSON. Both response attempts remain in provider spend; the observed document used one completed legacy document billing operation. The newer AI-credit quote path has separate idempotent operation settlement in code and existing tests, but no production credit-mode operation was examined in this incident.

The initial insights/entities cap values now live at `document_intelligence.structured_output_tokens`, read by `AnthropicClient::structuredCall`. - A representative, original-source, five-format corpus with full extraction-through-export assertions has not been assembled. Existing tests cover formats in separate layers; no claim of one complete five-format end-to-end gate is made.
- The existing incremental extraction instructions still describe the historical `metric_type=actual/target/change` and `value_basis=total/average/rate` wire convention. `CanonicalMetricIdentity` translates it, and field-role verification prevents unsupported promotion, but a versioned prompt/schema successor is needed to request the newer basis semantics directly. This was not silently changed under prompt version `2`.
- Reconciliation and comparison arithmetic now use an exact `BigDecimal` value from raw source digits. Chart display still uses floats, so large-number rendering and exact decimal chart serialization remain open; no currency conversion is performed without source rate evidence.
- The PDF parser stores page nodes but no table-cell nodes. The normal-route verifier covers unambiguous cited tabular rows/headers and one adjacent wrapped heading when it completes the table's column count, as on the Northstar proposal. Incremental PDF table cells, non-tab PDFs, OCR tables, regional column-only tables and more complex wrapped headings remain limited. `camelot` and `pdfplumber` are not installed locally; an auxiliary parser must be benchmarked against this corpus and five-format fixtures before deployment.

Inactive V9 asks for a source-supported entity/population only, but no paid V9 evaluation has shown that a model reliably follows it. Historical V8 records stay unverified. Future rejected candidates preserve only citation IDs and rejection codes for diagnosis; this does not retroactively recover the missing V8 response.
- Increasing initial output budgets may reduce retries but can increase admission reservations and maximal provider spend. Monitor per-purpose first-attempt `max_tokens`, success output-token percentiles, latency and estimated cost after any approved release. The two local incident samples do not establish a population-level optimum.
- The earlier read-only `git merge-tree` check found a worklog conflict between the V9 branch and `origin/main`; `integration/v9-source-windows` now contains that main merge and this document reconciles the content. This resolves the documentation conflict in the working tree, **not** the need for a fresh GitHub CI run or combined-branch backend/frontend testing. Pre-existing uncommitted V9 code and test edits are outside this documentation reconciliation and remain unvalidated here.

DOCX has no defensible page number or original Word layout; headers, comments, images and other content can be excluded as described by the [DOCX contract](../contracts/docx-structure-window.md). The gold fixture preserves `comparison_operator="<="`; the historical row does not. A typed comparator must be carried through extraction, evidence, comparisons, API and exports before that target can be treated as a general exact-value target.
