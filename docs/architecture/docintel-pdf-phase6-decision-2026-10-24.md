# ADR: restrict PDF financial tables before extending the parser

Date: 2026-10-24. Status: **decision for the next development phase; feature remains default-off**. Baseline: `bbfd4a5`. Evidence: [Phase 1–5 audit](../audits/docintel-pdf-table-structure-evaluation-2026-10-23.md) and [22 independently transcribed reference cells](../audits/docintel-pdf-phase5-reference-values.csv). This is an offline architecture and product decision, not approval to activate a beta.

## Decision

**Restrict the feature scope. Rank investment 1 first:** finish a reliable, explicitly limited native-text financial-table path and its operational safeguards. Do not implement balance sheets, segment/GAAP header dimensions or new section inheritance in this phase. Keep `DOCINTEL_PDF_TABLE_STRUCTURE=false` by default. Reconsider a canonical PDF source representation only if a broader reference corpus shows that exact Smalot projection is the *first* material loss after layout is recognized. The current evidence does not show that.

The principal bottleneck for useful coverage is **proving the complete relationship** from a number to its row, duration/date, unit, reporting scope and accounting basis. Geometry detects or can locate many values; the missing dimensions and governing context prevent safe facts. The dual-extractor projection is a real maintenance and coverage constraint, but it is not the leading observed cause of missing verified facts in the current corpus.

## Foundation and alternatives

The current route is `DocumentTextExtractor` → Smalot page text/offsets → Poppler `pdftotext -bbox-layout` word boxes → `PdfTableGeometryProbe` → exact `PdfTableStructureProjector` nodes → `StructuredExtractionStore` → separate `pdf-cell:` candidates → `TextRoleProvenanceProducer` / `SourceProvenance` → `StructuredPdfFieldProof` / owner and measurement gates → `MetricCollector` → `ChartCandidateBuilder` → `VerifiedPdfChartPersister`. The normal prose and OCR routes continue alongside it. Source sets are workspace/document/pipeline/revision scoped; `SourceProvenance` checks exact text, structural ownership and immutable graph hashes. Chart points retain value anchor, page and offsets. `SourceReferenceResolver` and the client require current revision and exact navigation; a failed projection emits no table cell, and prose remains available.

| Option | Cell and revision identity | Highlighting, OCR, failure behavior | Evidence for changing |
|---|---|---|---|
| **A. Retain dual extractors** | File hash plus stable projected cell ID; current Smalot text hash and provenance set pin proofs. | Exact text offsets and Poppler boxes permit current highlighting. Empty native pages use a separate OCR path and have no verified financial grid. Unmatched candidates are omitted; parser errors fall back to page text. | Already verifies Nasdaq and Apple comparisons with no observed false accept in the selected negative set. Apple needed a bounded multiline projection repair after fiscal-date parsing. The cross-extractor join is fragile for different reading orders and cannot represent a geometry-only cell in the existing proof contract. |
| **B. Canonical PDF source ledger** | One immutable, file-hash/parser-version-pinned page/word/cell ledger would give every table token an occurrence ID and geometry, with an adapter for existing prose offsets. | A PDF-point box could highlight without Smalot offsets; OCR would need its own image-coordinate ledger, confidence and revision policy. Failed table grouping could retain words but must publish no cell relationship. Workspace, document, pipeline and revision checks still apply; value/header/unit/owner verification cannot be relaxed. | Could eliminate the exact cross-extractor join and improve pages where a *recognized* grid cannot project. It would require a new navigation contract and migration/compatibility path. Apple now projects; UPS makes zero grid candidates before projection; Walmart lacks unit/date proof. No measured additional verified fact is attributable to a canonical ledger yet. |

Thus the join is a **structural ceiling**, especially for OCR and unusual text ordering, but calling it the current dominant bottleneck would confuse possible future coverage with observed recovery. A canonical source would not create UPS's repeated basis/segment headers or Walmart's missing table-specific scale.

## Initial product boundary

Support only native-text PDFs with a complete, same-page, aligned financial grid; at least two comparable, explicitly dated duration columns; exact row/value projection; an applicable caption or row-level unit/scale; one provable reporting owner; no unresolved segment, accounting-basis or share-count exception; and two verified points of one measure, unit, duration, basis and scope. Fiscal quarter ends need not be calendar month-end. Keep source-derived observations separate from model-derived observations and retain the printed row label, currency symbol and source value. A numerical match alone is a **raw extracted fact**, never a verified analytical fact.

Exclude scanned/rotated or geometry-poor tables, balance-sheet as-of grids, repeated GAAP/non-GAAP or segment columns, single-period composition tables, continuation pages without governing headings, ambiguous units/owners and unsupported aliases. Show the ordinary document/prose findings plus a clear **“Financial table comparison unavailable: source structure or verification incomplete”** state with the specific missing field and a jump to the page when known. Do not promise full financial analysis or silently infer a currency code, GAAP basis, year, or unit. Valid facts remain inspectable when no chart can be drawn.

Chart quality is a release issue: Nasdaq's 11 charts include related profit subtotals, components and specialized lines; title count is not value to a reader. Lead with a small number of independently useful outcome comparisons, retain all verified facts and accessible secondary charts, and validate prominence on Nasdaq and Apple. Each point must navigate to its exact source. The API currently has two chart routes: generated `analysis.visualAnalysis.charts`, and persisted `document.charts`. `ChartResource` recognizes only `document_visual`/`model_unverified`, so a persisted `verified_pdf_table` chart is reported as historical origin unavailable and ineligible. The frontend combines both arrays, potentially showing the same series twice. `AnalysisGrouper` groups all evidence by source ID, while model and source versions of an equivalent fact have distinct IDs; chart point deduplication does not deduplicate user-facing findings. These contracts must be reconciled before release without merging the two evidence origins or implying equal proof.

## Investment ranking

| Rank | Investment | User benefit and generalization | Verification, cost and change risk |
|---|---|---|---|
| **1** | Restricted reliable feature and operational safeguards | Demonstrated on two real issuers, with exact source navigation. Useful comparisons from clean statements; scope remains narrow. Fixes known API/UX and lifecycle gaps. | Reuses strict gates; modest incremental CPU/storage, no new inference. Medium product/API work; low parser risk. No activation until contract and retry/revision gates pass. |
| **2** | Canonical PDF provenance foundation | Potentially broad benefit for unprojectable native tables, highlighting and future OCR; no extra verified reference recovered by current evidence. | High migration, security, navigation and compatibility complexity; extra representation/storage and parser maintenance. Run a shadow experiment before funding. |
| **3** | Multidimensional financial headers/sections | Could reach UPS, balance sheets and some of 64 Nasdaq owner-rejected cells, but bounds are conditional and corpus is small. | Highest semantic false-acceptance and maintenance risk; more annotations/rules and likely inference temptation. Does not repair absent units or product contracts. |

No production usage, general false-acceptance rate, inference savings or customer value was measured. Rankings are evidence-weighted judgments, not quantified ROI.

## Operation and next experiment

On 2026-10-24, a disposable PostgreSQL 18 run of the rollback-only audit reproduced 128/44/11 cells/eligible facts/charts for Nasdaq page 8, Apple 132/18/4, UPS 0/0/0, Walmart 12/0/0, and Northstar 12/12/4. Nasdaq published 229 anchors/1,190 edges; Apple 273/1,283; UPS 15/0; Walmart 29/74; Northstar 30/74. Row payload (`pg_column_size`, excluding indexes/WAL) was 650 KiB, 641 KiB, 42 KiB, 74 KiB and 79 KiB respectively. One-process extraction→persistence stage sums were 1.51 s, 2.23 s, 0.75 s, 0.51 s and 0.25 s; the separate geometry audit pass is excluded. These are single local observations, not throughput or percentiles. The existing 128-cell fixture shows roughly 5 KiB persisted payload per candidate, but large-table growth remains untested.

Six focused backend tests passed (94 assertions) for duplicate chart points, changed-revision retraction, missing-extraction pruning, flag-off rejection, mocked merge-to-chart with no HTTP call, and completed-merge retry. Three existing frontend suites passed (61 tests) for chart and source navigation contracts, but none uses a `verified_pdf_table` response. A true HTTP upload through queued extraction to a browser chart, a forced crash between PDF collection and provenance publication, equivalent model/source findings in the public response, revision replacement through upload, and production resource percentiles remain unverified. The independently isolated ownership correction exists on `fix/docintel-incremental-ownership-review` (`72b5c07`, `7b3a363`); the flag-off tests confirm its behavior, but production compatibility impact is unmeasured. Review and release it separately.

**Single smallest next experiment:** one disposable, exact-hash Apple upload with a mocked equivalent model fact, run through the real queued jobs and both public document/intelligence responses, then replace that file revision and retry after an injected stop immediately following source collection. Assert one reader-visible verified comparison, one source jump per point, no duplicate model/source finding or chart, a visible limitation for unsupported balance-sheet cells, and no old-revision chart after retry. Record row counts and stage times. This tests the actual release contract and interruption seam; a failed gate directs the next safeguard. It does not require another parser rule, a paid call or a foundation rewrite.
